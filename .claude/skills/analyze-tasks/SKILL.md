# 분석과제 처리

사용자는 옵시디안에 분석할 거리를 과제로 적어 두고, 이 스킬로 그 과제들을 분석시킨다.
과제를 읽고 → 아직 안 한 것·바뀐 것을 고르고 → 분석하고 → 결과 노트를 쓰고 → 과제 노트에 결과를 잇는다.

## 경로

| 무엇 | 경로 |
|---|---|
| 과제 폴더 (입력) | `C:\Users\ocean\Documents\mv\Project\the-war-of-genesis\분석과제\` (하위 폴더 포함, 사용자가 자주 옮긴다) |
| 결과 폴더 (출력) | `C:\Users\ocean\Documents\mv\Project\the-war-of-genesis\분석\` |
| 게임 폴더 (읽기만) | `C:\Users\ocean\Desktop\창세기전3 파트2\` |
| 게임 DLL | 게임 폴더의 `G3PartII.dll` (PE32, ImageBase `0x10000000`) |
| 분석 도구 | 저장소 `tools/re/`, `tools/extract_character.py` |
| objdump | `/c/msys64/mingw64/bin/objdump` (Bash) |

옵시디안 링크(`obsidian://open?vault=mv&file=...`)를 받으면 `file=` 값을 URL 디코드해서 `Documents\mv\` 아래 경로로 바꾼다.
게임 폴더에는 절대 쓰지 않는다 — 풀어 낸 파일은 스크래치패드에 둔다.

## 1. 과제 읽기

1. 과제 폴더를 **매번 새로** 훑는다(`find ... -name "*.md"`). 이전 대화에서 본 파일 목록을 믿지 않는다 — 사용자가 파일을 옮기고 새로 만든다.
2. 과제 노트 형식(사용자가 쓰는 꼴):
   ```
   an-1
   캐릭터의 기본정보들 이름, first name, last name, 체질, 무기타입 분석
   ```
   번호 줄(`an-…`) 다음 줄들이 설명이다. 빈 줄로 과제가 나뉜다. 빈 파일은 과제 없음.
3. 과제마다 상태를 정한다:
   - 과제 바로 아래에 `→ 결과:` 줄이 없으면 **새 과제**.
   - `→ 결과:` 줄이 있는데 설명이 결과 노트의 "과제" 인용과 다르면 **바뀐 과제**.
   - `상태: 완료` 면 건너뛴다. `진행 중`이면 결과 노트의 "다음에 할 것"부터 이어서 한다.
4. **번호가 겹치면**(같은 `an-1` 이 두 번) 멋대로 번호를 바꾸지 말고, 분석은 하되 보고할 때 사용자에게 알린다.
5. 할 과제 목록을 사용자에게 한두 줄로 먼저 알리고 시작한다. 과제가 여러 개면 서로 독립인 것은 Agent 로 나눠도 된다.

## 2. 분석하기

먼저 결과 폴더의 기존 노트를 읽는다 — 이미 밝힌 것(주소, 파일 배치, 표)을 다시 파지 않는다. 특히
`분석-전투구성`, `분석-첫전투`, `분석-모션`, `분석-캐릭터`, `분석-링커맨드`. 알려진 사실 요약은 [reference.md](reference.md).

방법 순서(빠른 것부터):
1. **자료 파일 풀기**: `python tools/re/pak_extract.py "<게임 폴더>" <스크래치>/g Chr Dat Btl ...`
2. **텍스트로 뜻 잡기**: TXR 은 번호 하나로 찾는 전역 표다(`tools/extract_character.py` 의 `parse_txr`).
   메뉴 이름, 체질, 어빌리티, 지명 같은 것은 먼저 TXR 을 훑어 번호 범위를 찾는다.
3. **로더 찾기**: `python tools/re/dll_strings.py G3PartII.dll "<파일 서식 일부>" "Not Found"` → 문자열을 참조하는 코드 주소.
   한글 문자열은 `tools/re/dll_kstrings.py G3PartII.dll <출력.txt>`.
4. **로더 펼치기**: `objdump -d -M intel --start-address=0x... --stop-address=0x... G3PartII.dll`.
   `call 0x10006090`(fread 래퍼, 인자: 버퍼, 크기, 개수, 파일)의 순서·크기를 따라가면 파일 배치가 나온다.
   전역 표 주소를 누가 채우고 읽는지는 DLL 전체 디스어셈블을 스크래치에 한 번 떠 두고 grep 한다.
5. **데이터로 검산**: 풀어 낸 배치로 파일 전체를 읽어 파일 끝과 딱 맞는지, 값 분포가 말이 되는지 본다.
   덤프 스크립트는 `tools/re/chr_dump.py` 처럼 게임 폴더를 인자로 받게 만들어 `tools/re/` 에 남긴다.
6. **게임 실행으로 확인**(필요할 때만): 실제 게임은 DOSBox(Win95) 안에서 돈다. 사용자에게 화면까지 가 달라고 하고
   `python tools/find_current_battle.py` 처럼 `dosbox.exe` 메모리를 읽는다. 화면 캡처를 달라고 할 수도 있다.

추측과 확정을 반드시 나눈다. "파일 끝과 맞음", "DLL 이 이 필드로 이 텍스트를 고름", "게임 화면과 맞음"처럼 근거가 있으면 확정,
값 분포만 보고 짐작한 것은 가설로 적는다.

## 3. 결과 노트 쓰기

- 파일: `분석\분석-<주제>.md`. 과제 노트 이름에서 주제를 딴다(`분석과제-캐릭터` → `분석-캐릭터`). 이미 있으면 덮어쓰지 말고 절을 더하거나 고친다.
- 맨 위:
  ```
  # <주제> 분석 (<과제 번호들>)

  과제: [[분석과제-<주제>]] <번호> — <설명 그대로 인용>
  <날짜>. 상태: **완료** | **진행 중** — <한 줄 이유>
  ```
- 그다음 **결론 요약 표**(항목 | 결과 | 확실성), 그 뒤에 근거(주소, 파일 배치 표, 값 예시), 마지막에 `## 다음에 할 것`.
- 주소는 VA(`0x1003....`)로, 파일 오프셋은 10진수로 적는다. 다른 노트는 `[[분석-…]]` 로 잇는다.
- 글은 한국어 평문. 사용자가 읽는 노트이니 영어 약어·코드 이름은 처음 나올 때 풀어 쓴다.

## 4. 과제 노트에 잇기

과제 설명 바로 아래에 한 줄을 넣는다(이미 있으면 고친다). 사용자가 쓴 다른 줄은 건드리지 않는다.
```
an-1
캐릭터의 기본정보들 이름, first name, last name, 체질, 무기타입 분석
→ 결과: [[분석-캐릭터]] · 상태: 진행 중 · 2026-09-17
```
Edit 로 그 과제 블록만 고친다. Write 로 노트 전체를 다시 쓰지 않는다.

## 5. 보고

사용자에게는 과제별로 짧게: 무엇을 확정했고, 무엇이 가설이고, 다음에 무엇을 하면 되는지. 번호 겹침·빈 과제 파일도 알린다.
저장소에 새 도구를 만들었으면 그 경로를 알리고, 커밋은 사용자가 시킬 때만 한다.
